A goatty plugin packages a command-line tool so that someone who has never used it gets a good setup in one click. goatty downloads the tool into its own folder, shows the most useful options on the [Plugins page](goatty://settings/plugins) with explanations, and wires it into your [managed shell](/docs/using/managed-zsh), zsh on Linux and PowerShell on Windows.

Nothing outside goatty's own folders changes, and nothing runs as root.

## Built in

These come with goatty and are on by default:

| Plugin | What it does |
| --- | --- |
| `autosuggestions` | Ghost-text suggestions as you type |
| `syntax-highlighting` | Colors valid and invalid commands |
| `fzf` and `fzf-tab` | Fuzzy search for history, files and completion |
| `starship` | The prompt |
| `basics` | The built-in [snippets and expansions](/docs/using/snippets) |

Each has its own page under **Settings → Plugins**, where you can switch it off or change its options. Updates to their tools come with goatty releases.

## Install a plugin

<Steps>
1. Open [**Settings → Plugins**](goatty://settings/plugins), or the palette: **Plugins: browse, install and configure**.

2. Pick a plugin from the registry.

   Permission badges show what each one can do.

3. Choose **Review & install…**.

   goatty shows the full plan: what is downloaded (with checksums), the permissions it asks for and why, the aliases and environment variables it adds, and a **Read the code** link for any shell code. If the plugin needs other plugins, their plans are included.

4. Choose **Install**.

   You can watch progress and cancel until it's activated.
</Steps>

Installed plugins show their settings as normal controls with help text. Their edits go through the same [Preview / Apply](/docs/customize/settings#preview-then-apply) draft as your other shell settings, and, when you edit under *All synced hosts*, they [sync to your other hosts](/docs/customize/sync).

### Examples from the official registry

| Plugin | Sets up |
| --- | --- |
| [**eza**](goatty://plugins/eza) | A modern `ls`, with icons, grouping, git column and tree depth options |
| [**zoxide**](goatty://plugins/zoxide) | Jump to directories you use often, with `z` |
| [**bat**](goatty://plugins/bat) | `cat` with syntax highlighting and goatty's colors, also used for man pages |
| [**atuin**](goatty://plugins/atuin) | A searchable history database on <kbd>Ctrl</kbd>+<kbd>R</kbd> |

[Browse them all](goatty://plugins), or run `goattyd plugin search`. A plugin can also add commands to the palette and your own shortcuts.

## Keep plugins up to date

goatty checks for new versions in the background and tells you, but never installs anything on its own. An update shows only what *changed* from the version you have, and asks for a fresh review when the new version can do something the old one couldn't. You can turn the notices off with [Tell me about plugin updates](goatty://settings/plugins?setting=plugins.notify_updates).

## Permissions and trust

Plugins ask for specific permissions: install programs, add aliases, set environment variables, write config files, add palette commands, add snippets. The ones that run code (`binaries`, `shell-code`) must explain why.

<Aside type="caution" title="A signature isn't a safety guarantee">
  The official registry is signed, and goatty only accepts it with its pinned key, so you know where a plugin came from and that it wasn't changed. That doesn't make a program harmless. Read the plan before you install, especially anything that runs shell code.
</Aside>

What you approve is exactly what is installed: if the plan changes between review and install, goatty refuses. Other registries can be added, but only together with their public key (`goattyd plugin registry add`). There is no trust on first use.

## From the command line

On the host:

```bash
goattyd plugin search eza     # what registries offer
goattyd plugin info eza       # settings, permissions
goattyd plugin install eza    # prints the plan, then asks [y/N]
goattyd plugin list           # installed, with updates and problems
goattyd plugin update         # newer versions, same review
goattyd plugin set eza KEY VALUE
goattyd plugin disable eza    # keep it installed, out of the shell
```

## Write your own

Plugins are plain TOML manifests. The [plugin template](https://github.com/goatty-dev/goatty-plugin-template) is a complete, commented example and includes a Claude Code skill to help you write one. Test a local plugin with `goattyd plugin install --path ./my-plugin`. To get one into the official registry, see [goatty-registry](https://github.com/goatty-dev/goatty-registry).

A plugin can limit itself to some systems or shells (`os`, `shells`), so one plugin can support zsh and PowerShell. The full manifest format is in the [plugin technical docs](https://github.com/goatty-dev/goatty/blob/main/docs/plugins.md).
